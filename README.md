# scraper

خدمة تحديث روابط المشاهدة (m3u8) لقاعدة بيانات cinevault. تحل محل الفوضى
اللي كانت متوزعة على 3 مجلدات (`video-scraper`, `folim-scraper`, وملفات
داخل الموقع نفسه) بخدمة واحدة موحدة، **topcinema فقط** (faselhd أُزيل نهائيًا).

## المبدأ: تحديث عند الطلب، مو مسح كل القاعدة

نحدّث بس العنوان اللي زائر حقيقي فتح صفحته أو حاول يشغّله — مو نمسح
آلاف الروابط اللي محد يشوفها. لما رابط يموت، الموقع نفسه يطلب تحديث
مستهدف لهذا العنوان بس (يوصل خلال دقيقة أو دقيقتين عادة)، والفحص الدوري
العام يشتغل نادر جدًا كشبكة أمان بس.

## الملفات

- `config.js` — الإعدادات المشتركة (مصدر topcinema، قائمة السيرفرات، فحص انتهاء الصلاحية + فحص حي حقيقي).
- `lib/resolver.js` — المنطق الأساسي: يبحث عن عنوان بـtopcinema، يتحقق الروابط شغالة فعليًا قبل ما يكتبها.
- `lib/reporter.js` — يكتب تقرير لكل تشغيلة.
- `refresh-one.js` — يحدث **عنوان واحد بس** (`TITLE_ID`/`EPISODE_ID`) — هذا اللي يشغّله الموقع عند الطلب.
- `run-scheduled-check.js` — مسح عام لكل الروابط المنتهية — احتياطي، نادر الاستخدام الحين.
- `server.js` — سيرفر Express دائم (بديل لو قررت تدفع لاستضافة لاحقًا؛ غير مستخدم حاليًا).

## كيف يشتغل (كل شي مجاني، بدون بطاقة ائتمان)

```
زائر يفتح صفحة فيلم/حلقة
        │
        ▼
الموقع (TitleHero / المشغل عند فشل كل السيرفرات)
        │  POST /api/refresh-server { title_id, episode_id? }
        ▼
route.ts يتحقق:
  - فيه رابط شغال فعليًا؟ (HTTP check) → ما يسوي شي
  - نفس العنوان له طلب تحديث بالـ3 دقائق الماضية؟ → يتجاهل (منع التكرار)
  - تجاوزنا 8 طلبات بهالدقيقة؟ → يتجاهل (حماية الميزانية المجانية عند ازدحام كبير)
  - غير كذا → يطلق GitHub Actions workflow_dispatch
        │
        ▼
.github/workflows/refresh-single.yml يشتغل على GitHub (~1-2 دقيقة)
        │  node refresh-one.js
        ▼
lib/resolver.js يبحث بـtopcinema، يتحقق الرابط شغال، يكتبه بقاعدة البيانات
```

## إعداد لمرة وحدة

**1) GitHub — Settings → Secrets and variables → Actions:**
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

**2) GitHub Personal Access Token** (يحتاجه الموقع نفسه عشان يطلب من GitHub
يشغّل الـworkflow):
- روح https://github.com/settings/tokens → Generate new token (classic)
- صلاحية `workflow` بس كفاية
- انسخه، وحطه بمتغيرات بيئة Vercel (أو أي استضافة للموقع) باسم `GH_DISPATCH_TOKEN`

**3) تأكد `UPSTASH_REDIS_REST_URL` و`UPSTASH_REDIS_REST_TOKEN`** موجودين
بمتغيرات بيئة الموقع (أصلاً مستخدمين لأشياء ثانية بالمشروع — نفس الحساب يكفي).

بعد كذا كل شي يشتغل تلقائي — مافيه خطوة يدوية تانية.

## هل يتحمل 500 زائر بنفس الوقت؟

نعم، مصمم لهذا بالذات:
- **فحص قبل أي تحديث**: أغلب الطلبات ما توصل GitHub أصلاً لأن الرابط يطلع شغال من الفحص السريع.
- **منع التكرار**: لو 500 زائر يشوفون نفس الفيلم الميت بنفس اللحظة، وحد بس يطلق التحديث؛ الباقي ينتظرون نفس النتيجة (قفل Redis 3 دقائق).
- **حد أقصى 8 تحديثات/دقيقة إجمالاً**: حتى لو 500 عنوان مختلف ماتوا بنفس الوقت (احتمال ضعيف جدًا)، ما نطلق أكثر من 8 تشغيلات GitHub بالدقيقة — يحمي من تجاوز حد GitHub لعدد المهام المتزامنة (20 بالخطة المجانية) ومن استهلاك الميزانية الشهرية بسرعة.

## الميزانية المجانية (GitHub Actions)

2000 دقيقة/شهر مجانًا (private repo). المسح العام (`refresh-links.yml`)
صار كل 12 ساعة بس (شبكة أمان، مو الاعتماد الأساسي) — أغلب الميزانية
محجوزة للتحديث الفوري عند الطلب. لو حسيت الميزانية تنخلص بسرعة زيادة عن
المتوقع، قلل `MAX_DISPATCHES_PER_MINUTE` بملف
`src/app/api/refresh-server/route.ts`.

**الكمية المتراكمة حاليًا** (~22 ألف رابط منتهي من قبل هالتحديث): برضو
راح تتصفى تدريجيًا كل ما زائر يفتحها — مو دفعة وحدة. لو تبي تسرّع التنظيف
الأولي لعناوين معينة بدون انتظار زوار، شغّل محليًا:

```bash
npm install
cp .env.example .env   # عبّي SUPABASE_URL و SUPABASE_SERVICE_ROLE_KEY
node run-scheduled-check.js   # بدون MAX_RUN_MINUTES = يشتغل لين يخلص كل شي
```

هذا يستخدم كهرباء جهازك أنت، مو دقائق GitHub المجانية.

## شنو اتحل من الفوضى القديمة

كان فيه 3 نسخ متكررة من نفس الفكرة بمجلد `folim-scraper` القديم:
`server.js`+`scraper.js`, `movies-server.js`+`movies-scraper.js`,
`srsserver.js`+`series-scraper.js` (هالأخيرة كانت مكسورة أصلاً — بتطلب
ملف باسم غلط ما هو موجود). دُمجوا كلهم هنا. `video-scraper` (مجلد منفصل
قديم) كان محاولة أقدم متروكة قبل هالمرحلة، غير مستخدمة حاليًا.

كمان لقينا خطأ إملائي بـ`TitleHero.tsx` كان يمنع آلية التحديث عند الطلب
من الاشتغال من الأساس (كانت ترسل `titleid` بدل `title_id`) — انصلح.

## الباقي (المرحلة الجاية)

سكربتات استيراد عناوين/حلقات **جديدة** (مو تحديث الموجود) لسا بمجلد
`folim-scraper` (`movies-scraper.js`, `series-screaper.js`) — ما نُقلت
لهنا بعد، تحتاج نفس المعالجة (فحص + إزالة faselhd + دمج).
